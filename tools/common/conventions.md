# 共通の決まり — 全エージェントが守ること

各エージェントの README より先に読む。ここに書いてあることは、どのエージェントも変えない。

## リポジトリの扱い

- **読むだけ。** commit・push・PR を作らない。例外は1体目（ハブ更新）の `index.html` だけで、それも `claude/` で始まるブランチ → PR → Skyがマージ。`main` には誰も直接書かない
- 数字はダッシュボードのDB、図はアーティファクト、報告は通知に出す。リポジトリに数字やファイルを書き戻さない（書き戻すエージェントが要るときは、別のリポジトリを作る）
- **秘密・非公開のものはここに書かない。** URL（ダッシュボード・アーティファクト）、メールアドレス、ID、パスワード、トークン。これらは起動時の指示文（ルーティンの設定、非公開）にあり、手順書は「指示文にある」と書くだけにする
- このリポジトリは公開で、`tools/` は `_config.yml` でサイトの配信から外してある（GitHub上では読める）

## 数字の決まり

- **未計測は null。** 0 にしない、前回の値で埋めない、推定しない。読めなかった理由を memo に書く
- **時点を統一する。** 1回の集計で作る行・図・報告はすべて同じ集計時点（REC）。図の「◯◯時点」は実際に読んだ時刻を使う
- **REC と行のID：** `YYYYMMDD-HHMM`（日本時間、分は10分単位に切り上げ。例 16:29に読み終えたら `20260924-1630`）。同じ日に2回やるなら別のID
- **N日目：** 2026-09-06（5つのSNSに投稿を始めた日）からの経過日数。9/6が0日目、9/24が18日目。`Math.round((REC日 - 2026-09-06) / 86400000)`
- **前回差の基準は「前回に公開した記事の図」。** 直前の集計ではない。基準の行IDはDBの `meta/baseline` にあり、更新されるのは Sky が起動テキストで記事のURL（`記事：…`）を渡したときだけ（その記事の公開時刻の直前の集計＝その記事の図）。前回の図に無かった行は `NEW`
- **GA4の数字は読んだ日で変わる**（直近1〜2日は後から増え、参照元が振り直される）。GA4の前回差は「前回の期間を今日読み直した値」と比べる。前回の引き継ぎに書いてある値をそのまま基準にしない
- 既存のDBの行は書き換えない・消さない。新しい行を足す。訂正が要るときは新しい行の memo に書いて報告する

## 言葉

- SNSの数字は「表示・再生」「いいね」「フォロワー」「投稿」。「媒体」は使わない（「SNS」「5つのSNS」）
- ハブページは、記事では「まとめページ」、GA4は「Googleアナリティクス」と言い換える（図・DB・引き継ぎでは「ハブページ」「GA4」のまま）
- 「クリック」は人数ではない（同じ人が複数回押した分を含む）。「人」と書かない
- 「バズった」「◯倍」などの煽り表現を使わない。伸びた、は数字で言う

## 報告（Skyのスマホに届く）

- 短く。`---` で囲み、Skyがその場で判断できる分量（数字・前回差・読めなかったもの・次にSkyがやること）
- 読めなかったものは必ず書く。「全部読めた」と書けるのは、本当に全部読めたときだけ
- 質問で止まらない。判断に迷ったら、もっとも安全な読み（何も壊さない・nullで残す）を選び、そう読んだと書く

## ブラウザ（Claudeアプリ内のブラウザペイン）

- Skyのログインが残っている。パスワードを入れようとしない。ログイン画面が出たら、その媒体は null にして報告する
- ペインの幅が狭いとモバイル版で描画されてPC版の数字が出ない。読む前に 1280×900 にする
- スクリーンショットは古い画面を返すことがある。数字はDOM（JS）で読む
- 数字を読むだけ。投稿・削除・設定変更・保存ボタンを押さない
