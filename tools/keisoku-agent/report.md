# report.md — 報告と引き継ぎの型

## 報告（Skyのスマホに届く。最後の出力）

短く。Skyがその場で判断できる分量。読めなかったものを隠さない。数字は3桁区切り、前回差は括弧。

```
---
集計 2026/09/24 16:30（18日目）
SNS 表示・再生 24,241（+5,379）／投稿 85（+15）／フォロワー 73（+38）／いいね 144（+65）
noteへのクリック 97（+7）＝短縮リンク78＋ハブ経由10（着地59のうち）＋コタロウ→検証室9
検証室note imp 6,256（+1,630）／pv 446（+74）／スキ 27（+15）／フォロワー 12（+9）／記事 9
コタロウ imp 11,501／pv 560／スキ 240／フォロワー 202
動いたもの：TikTok #07画像投稿 1,753・Threads #07スレッド 757・noteスキ+15（自己紹介+9）
読めなかったもの：なし
DB：REC 20260924-1630（records・clicks・kotaro・accounts 5・snaps 85・posts 新規16）
図版：4枚を差し替え済み（前回差の基準 9/21 17:40の図）
次の記事を出したら、起動テキストに「記事：<noteのURL>」を付けて
---
```

- 「読めなかったもの」の書き方：`00Min（ログイン切れ）→ クリックの図と見出し画像は作っていない`／`noteスクショなし → imp・pv は null`／`Instagram（ログイン画面）→ null`
- ブラウザに届かなかったとき：`Macに届かなかった（Claudeアプリが開いていない可能性）。何も書いていない。` の1行だけ
- 前回差の基準が `meta/baseline` 以外だったときは、その旨を1行足す

## 引き継ぎ（`handoffs/<REC>` の `md`。書けるならプロジェクトdoc `横並び検証室/引き継ぎ_YYYY-MM-DD.md` にも）

これまでの引き継ぎと同じ形。

```markdown
# 引き継ぎ YYYY-MM-DD（N日目・本番集計）

**YYYY/MM/DD HH:MM 時点**で6媒体＋00Min＋GA4＋note（検証室・コタロウ）をそろえた。図版4枚・アーティファクト「SNS実験の図版」・ダッシュボードDBとも同じ時点。前回差は **前回の記事の図（M/D HH:MM）** との差。

- DBの行ID：`records/<REC>`、`clicks/<REC>`、`kotaro/<REC>`、accounts `*-<REC>`、snaps `*_<REC>`（N本）
- 台帳の変更：posts に新規N本／posts_removed へ N本／articles に追加

## 数字（前回の記事 M/D HH:MM → 今回）

| | 前回 | 今回 | 差 |
|---|---|---|---|
| SNS 表示・再生 | | | |
| SNS 投稿 | | | |
| SNS フォロワー | | | |
| SNS いいね | | | |
| noteへのクリック | | | |
| ハブ着地（`/`だけ） | （読み直し） | | |
| 検証室note imp／pv／スキ／フォロワー／記事 | | | |

媒体別：YouTube ◯（N本、登録者◯）／TikTok ◯（N本、フォロワー◯・いいね◯）／X ◯（N本）／Instagram ◯（N件）／Threads ◯（N本）。
クリック：短縮リンク◯＋ハブ経由◯（着地◯のうち）＋コタロウ→検証室◯。SNS別 YT・TT・X・IG・TH・note（コタロウ）・参照元なし。
コタロウ：imp・pv・スキ・フォロワー・フォロー。

## 今回の投稿（前回の集計以降。数字は今回時点）

- M/D HH:MM 媒体：内容 → 数字

## メモ

- 読めなかったもの・据え置き・注意点（GA4の振り直し、Instagramのダッシュボードの遅れ、など）
- 次回への申し送り
```
